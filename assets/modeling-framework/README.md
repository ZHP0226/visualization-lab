# 可视化实验室 · 结构拆解与可复现建模 1.0

第二步A先拆结构，第二步B再执行代码。本目录随软件免费提供，并复制到每个使用框架的项目交付前缀 `_reproduction` 目录，包含方案、代码与检查记录；不是参考图片库。

## A. 拆解整体结构

先读取原图，按 `example.structure.json` 保存 `structure.json`。坐标为右手 Z 向上；尺寸和相机统一使用同一项目单位。对象用稳定英文 ID，显示名可中文，明确分组、形状、尺寸、位置与材质。相机、灯光、分辨率、采样与种子全部显式记录。

`assumptions` 写下遮挡、厚度、背面、尺度等无法从原图确定的假设；`review.differences` 记录原图与实际渲染之间尚存差异。单张参考不等于唯一的三维真值。默认 `review.status=pending`，实际看过成图后才可以改为 reviewed；它也不等于用户验收。工作台工具自动填写真实原图路径、摘要与尺寸，不能换用别的图片。

## B. 根据代码建模和检查

先核实已安装软件，用户未选择本次软件时询问后再制作。默认后台脚本，不用电脑操控。示例命令（路径请换成本轮实际路径）：

```
python run.py --software blender --executable "D:/Blender 5.2/blender.exe" --plan structure.json --stem "D:/项目/主题_v001"
python run.py --software c4d --executable "G:/Maxon Cinema 4D R21/c4dpy.exe" --plan structure.json --stem "D:/项目/主题_v001"
```

流程：验证方案及原图摘要 → 创建独立对象 → 保存原工程 → 重新打开原工程 → 读取实际计算后网格并检查对象清单与尺寸位置 → 导出内嵌 GLB → 实际渲染 PNG → 保存 `audit.json`。后台登记再次比较文件摘要、对象ID、三角形与包围盒。检查失败不算交付。

复现成图使用同目录的代码和原工程，不覆盖原图：

```
python run.py --software blender --executable "已安装的软件路径" --plan structure.json --stem "原交付完整前缀" --replay-output "复现检查.png"
```

原图移动后需要在方案中重新定位并核实摘要。若改方案，必须重新建模、渲染并生成审计；不要复用旧审计。保留当时软件版本与环境，复现时比较图像像素和差异，不能只凭文件存在宣称复现成功。

## 当前适配范围

- 基础几何为 box、sphere、cylinder，可用同种参数生成阵列与分组。尚未覆盖任意曲面、文字、复杂布尔、动画、插件或物理仿真。
- 复杂几何使用 `shape=custom`，需另写项目脚本。保留基础文件原件，复用 `load_plan`、`geometry_audit`、`write_glb`、`write_audit`；实际计算后网格必须具有方案中相同ID。项目脚本也随交付保存。custom 的尺寸仅供方案描述，需项目脚本另行核验拓扑和形状。
- Blender 使用 Cycles CPU、固定采样和种子、Standard色彩变换，支持透视和正交相机。C4D R21 基线为 Standard CPU、透视相机、固定抗锯齿与基本颜色/高光材质；其灯光强度、材质与采样语义不等于 Cycles。C4D 正交/复杂反射需单独实现并验证，当前不默默近似。
- GLB 保留对象、分组和基础PBR参数，供工作台查看结构；最终外观以原软件的真实PNG为准。原生材质、灯光和特效不保证由GLB完整重现。
- 同一软件与硬件中的重复渲染可比较像素；不同软件、版本、硬件和插件的位级一致性不作保证。审计用于完整性和复现追踪，不能替代科学正确性和人工视觉审查，也不是防恶意伪造的安全证明。

普通模型小修改沿用现有工作流；只渲染已有模型不必重建框架或增加模型版本。独立图片修改使用生图/改图能力，不走本建模流程。
